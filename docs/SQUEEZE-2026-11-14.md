# Mini squeeze plan — ranked upgrades (2026-11-14)

Goal: maximum reliable throughput/quality from the 8 GB Intel box without
new hardware. Evidence: `UPGRADE-runtimes` + `UPGRADE-decoding` deep dives
(primary sources, both in `docs/`), Nov 13–14 campaign numbers.

Conventions: each item has expected effect, cost, owner lane (w46 Mini
exec vs w47 Flappy/reach lane), and a falsifiable test. Tiers are ordered;
do not skip tiers (later items assume earlier ones hold).

## Tier 0 — do now (config only, reversible)

1. **Pin + serialize Ollama**: `OLLAMA_KEEP_ALIVE=-1`,
   `OLLAMA_MAX_LOADED_MODELS=1`, keep `OLLAMA_NUM_PARALLEL=1`, ctx 4k.
   Kills reloads and eviction churn. Owner: w46 (Mini env).
   Test: idle 6+ min, re-request, `load_duration` ≈ 0.
2. **`format`=schema + temp 0 on all judge/voter calls** (works on both
   `/api/chat` and `/v1`). Kills the biggest parse-failure class for free.
   Owner: w47 (harness edits). Test: rerun voter-18 on 3 chatty models,
   count `?` verdicts before/after.
3. **Lock in `NUM_PARALLEL=1`** as decided (no slots on 6 CPU cores).
   Owner: w46 with item 1. No test (decision).

## Tier 1 — measure this week (test-gated)

4. **Prefix-cache verification**: pin model, freeze template, send same
   system prompt + varying suffix twice; compare `prompt_eval_cached_count`
   (0 → N) + `prompt_eval_duration`. Negative control: perturb one early
   token, confirm collapse. Owner: w46 (needs the pinned env from 1).
5. **KV `q8_0` matrix**: `OLLAMA_KV_CACHE_TYPE=q8_0` × FA unset/1/0.
   Record RSS + tok/s ×10 + load errors. If no RAM drop vs f16, KV quant
   is not engaging on CPU — abandon, do not force. Owner: w46.
6. **Judge JSON audit**: run the 41-model roster once through a strict
   `format`=schema call; any model that cannot emit valid JSON is
   disqualified from judge duty (generator-only). Owner: w47.

## Tier 2 — conditional (only on measured need)

7. **imatrix I-quants** — only if RAM still binds after 1–5. Per-model
   calibrate → quantize → PPL-gate (same model/data/binary) → `FROM`
   import. Buys hundreds of MB, not speed. Owner: w46.
8. **Grammar rollout to tools** — only after `format` proves insufficient
   on the T12 bench. GBNF via llama.cpp templates; NobodyWho patterns as
   reference. Owner: w47 (harness) + w46 (server flags if needed).
9. **Model-fit picker** — only if OOMs recur after 1–8. Smallest correct
   shape: preflight table (RAM + quant + ctx → runs/swaps), not a service.
   Owner: w47.

## Explicitly NOT doing (evidence against)

- **llama.cpp migration for speed**: Ollama 0.40+ IS llama-server; expected
  CPU gain ≈ 0–7% against a full rewrite of addressing/lifecycle/proxy.
  Revisit only for a missing flag.
- **Atomic TurboQuant layer**: KV win immaterial at 4k/small/CPU; thinner
  serving surface; fork costs. Revisit only for long-context need.
- **Draft-model speculative decoding**: second resident model breaks the 8 GB
  budget. N-gram predictor may be revisited with llama.cpp numbers.
- **Parallel slots**: sublinear throughput, ≥2× latency, swap risk. Revisit
  only under real concurrent load.
- **Qwen3-Coder-30B via colibri as daily driver**: proven to run (correct
  fib, ~1 tok/s cold) but needs 19 GB disk + ~8 GB RAM of a box that has
  15 GB / 8.6 GB. Specialist batch jobs only, never alongside Ollama.

## Validation floor

Every Tier 0–1 item lands with: the exact command/env diff, before/after
numbers from the prescribed test, and a rollback line. No item is "done"
without all three in the commit message or a dated note.
