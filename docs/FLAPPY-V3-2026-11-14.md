## False-positive classes v3 killed (with root causes)

1. **Glacial delta-time physics** (qwen3:8b R2): `velocity += g*dt` scaled ~60× too slow;
   v1/v2 thresholds passed creep as flap; v2 scores were load-luck (throttled rAF teleports).
2. **Static-decal bird** (gemma4 R2): physics updated `birdY`, render/hooks read `bird.y`
   (never assigned); pipes auto-scrolled and scored by luck. v3 flight filter: auto=1 flown=0.
3. **Floorless + input-dead** (Artemis R1): no input response, dies mid-screen. Floor check + caps.
4. **Over-press autopilot regression** (ours, caught by ref-good 80): chained presses pinned
   vy at flap velocity; fixed with press-only-when-falling controller (probe `[DBG-flap1]`).

## Structural findings

- **Repairs can HURT**: gemma4 R1 90 → R2 35; qwen3:8b R1 60 → R2 35. Matches research
  ("Feedback Over Form" negative result: open-ended revision breaks working games).
- **T3 snippet skill ≠ app coherence**: nemotron-3-nano:4b (T3 65, T1 4/4) wrote 35-line
  skeletons twice (v3 retry 25/30); qwen2.5-coder:1.5b (T3 mid) reached 60.
- **Calibration wrinkle**: `visible` samples the first 600ms, so legit tap-to-start screens
  fail it. Both 90s fail ONLY this gate. Next grader rev: sample post-first-input too.
- **Load-dependent grading**: delta-time games + throttled rAF = random scores across runs.
  v3 controls it by running both scoring arms back-to-back in one load window.
